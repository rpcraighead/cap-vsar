Hardware Specifications & Deployment Guide

Deploy CAP V-SAR seamlessly—from an individual volunteer's home desktop workstation to a full squadron multi-station simulator lab or a wing-wide distributed exercise. Automated scripts handle airframe generation, instrument deployment, and container launch.

Architectural Scalability

Three Turn-Key Deployment Topologies

Choose the deployment model that matches your unit's facilities, hardware inventory, and training scope.

Topology A • Personal / Detachment

Standalone All-in-One

All simulation roles run on a single PC equipped with dual monitors. Perfect for home study, individual qualification renewal, and desktop practice.

  • ✓ Display 1: X-Plane 12 flight deck (C182T G1000 3D cockpit).
  • ✓ Display 2: Air Manager MO Station panel (Becker 517 / RT-600) and web console.
  • ✓ Local Services: Docker containers run quietly in background on localhost.
Topology B • Squadron Sim Lab (Recommended)

Multi-Station LAN Sim Bay

Full multi-crew tactical simulator bay providing authentic Crew Resource Management (CRM) between Pilot, Observer, and Ground Dispatch.

  • ✓ Pilot Station: Primary PC with yoke, rudders, throttle quadrant, and G1000.
  • ✓ MO Station: Dedicated secondary PC or tablet with touch-screen Air Manager panel.
  • ✓ MRO Console: Tablet running APX 6500 & IC-A120 virtual radio console.
  • ✓ Incident Command: Instructor console with live map and beacon controls.
Topology C • Wing-Wide Exercise

Distributed Cloud WAN

Connect multiple aircraft and geographically dispersed squadrons into unified wing-wide search operations over secure internet connections.

  • ✓ Cloud Server: Central exercise host on cloud VPS (AWS/Azure) or Wing HQ.
  • ✓ Multi-Aircraft Sorties: Simultaneous tracking of multiple flight crews.
  • ✓ Tactical Voice: Low-latency Mumble bridge connecting remote home stations.

Automated Setup Pipeline

Step-by-Step Installation Commands

CAP V-SAR includes automated setup scripts that build the airframe package, deploy the Air Manager instruments, and register the multi-layout MO station panel in seconds.

Step 1: Clone Repository & Build Cessna 182T Skylane Package

The package builder script reads your local X-Plane 12 C172SP G1000 base, upgrades the flight model to 230 HP Lycoming IO-540 specifications, enables the constant-speed propeller governor, and configures the G1000 EIS for dual Manifold Pressure and RPM gauges:

bash — Build C182T Airframe 
# Navigate to repository root
cd /srv/capvsar

# Build dedicated Cessna 182T NAV III standalone package
python3 scripts/build_c182t_package.py \
  --xplane-dir "/opt/x-plane-12" \
  --tail-number "N499CP" \
  --overwrite

Step 2: Deploy Direction Finding Instruments & MO Station Panel

Deploy the custom Becker SAR-DF 517, RHOTHETA RT-600, Technisonic TDFM-136B, and Garmin GMA 1347 instruments to Air Manager 4.2+, then inject the panel into Air Manager's SQLite database:

bash — Deploy Avionics to Air Manager 
# Deploy instrument code and vector assets to Air Manager instruments directory
python3 scripts/deploy_df_instruments.py

# Deploy panel definition (panel.xml, background textures, canvas coordinates)
python3 scripts/deploy_mo_panel.py

# Register panel in Air Manager config.sqlite3 database
python3 scripts/register_mo_panel.py

Step 3: Launch Docker Services (Exercise, Radios, Flight Planner)

Start the exercise backend, MRO base radio web server, flight planner, and Mumble voice server:

bash — Launch Docker Microservices 
# Launch background container suite
docker compose -f docker-compose.prod.yml up -d

# Verify container health status
docker compose -f docker-compose.prod.yml ps

Step 4: Run Automated Verification Test Suite

Execute the automated test suite to confirm flight model parameters, instrument dimensions, and panel layout database registrations:

bash — Run Pytest Validation Suite 
# Run complete unit test suite
pytest tests/test_engine.py tests/test_faceplate.py tests/test_panel.py -v

Step 5: Provision Multi-Aircraft Station Kits

For multi-station squadron labs or remote distributed aircrews, generate turnkey self-contained installer packages for each aircraft. The builder generates capvsar_station.ini (console URL, callsign, and authentication key) bundled with pristine X-Plane plugins and Air Manager instruments:

bash — Generate Station Kits 
# Generate standalone installer zip for Aircraft 2 (CAP-2)
python3 scripts/build_station_kit.py \
  --callsign "CAP-2" \
  --console "http://192.0.2.151:8700" \
  --zip

# Generates: dist/capvsar_station_CAP-2.zip containing:
#  ├── PI_capvsar_df.py      (Tracked plugin source, byte-identical across fleet)
#  ├── capvsar_station.ini   (Station console URL, callsign, and auth key)
#  ├── instruments/          (Becker 517, RT-600, TDFM-136B, GMA 1347)
#  └── README.md             (Target copy paths for X-Plane & Air Manager)
Firewall & Ports

Network Port Configuration Matrix

Ensure the following TCP and UDP ports are open on your local firewall or router for multi-station and remote exercises:

Port Protocol Service Name Description / Purpose
8700 TCP Exercise API & Base Radio Web consoles: MRO Base Radio (/radio), Mission Base (/base), Debrief (/debrief), REST API.
8090 TCP N499CP Flight Planner Web mapping frontend serving FAA VFR sectional tiles and FMS flight plans.
64738 TCP / UDP Mumble Voice Server Low-latency tactical voice communication between aircrew and base.
49000 UDP X-Plane Telemetry In Receives high-rate flight dynamics, positioning, and engine datarefs from X-Plane.
49001 UDP X-Plane Dataref Out Transmits DF bearing cuts, beacon activations, and RF squelch states back to aircraft.
