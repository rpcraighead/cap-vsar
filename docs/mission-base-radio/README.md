# Mission base headset radio

The web radio at `https://<mission-host>/radio` (the server's name or address
on the mission network; the pages build their own links from the address they
were opened on) connects tablet and computer operators to the existing CAP V-SAR
Mumble mission nets. Select an APX 4500 or EFJohnson 5300 face, pair a headset
in the device settings, enter a callsign, choose a net for each radio, and join.
Hold the touch button or spacebar to speak; release to listen. Both skins are
the same tactical radio; the second receiver is described below.

First-time setup is at
`https://<mission-host>/static/radio-help.html`.
Install the server's public CA certificate from
`http://<mission-host>/radio-ca.crt`, then open the HTTPS radio page. This public
certificate is the only plaintext response; every other HTTP path redirects to
HTTPS. The certificate is generated locally by Caddy; each device must
explicitly trust it. Its private key stays in Caddy's Docker data volume. No
browser security flags or certificate-warning bypass are part of the operator
setup.

Bluetooth pairing and audio routing use the operating system. The app offers
microphone selection, output selection where `AudioContext.setSinkId` is
supported, a local headset sound test, and receive volume. Safari and other
browsers without output selection use the system audio route. Headset hardware
call buttons are not mapped to PTT. Keep the page visible and device awake.

## Two radios and the Form 110 log

**Dual receiver (F-10).** Every operator holds two Mumble sessions: the
*tactical radio* (the faceplate) and the *airband radio* (a second panel under
it, "RADIO 02 / AIRBAND"). Each has its own net selector and volume, and a
PTT-transmitter selector chooses which one keys; both keep receiving. Both
radios pick from the same four mission nets (airband proper is PilotEdge's, in
X-Plane, not a channel here), and the page keeps them on different nets: moving
one onto the other's net moves the other. A failure on the airband radio stops
only that radio, retried every five seconds; the tactical radio is torn down
only by its own failures. Sidetones follow the keyed radio (P25 chirp and tail
on tactical, AM click and squelch burst on airband, F-11), and the EFJohnson
face's MON key opens that radio's squelch (F-12).

**Session capacity.** `CAPVSAR_RADIO_MAX_SESSIONS` (default 16) counts
sessions, not people, and a dual-radio desk uses two. Sixteen sessions is
therefore **eight dual-radio desks** (`maxDualRadioOperators` in
`/api/radio/config`). The ninth operator keeps the tactical radio and is told
the airband radio could not connect.

**CAP Form 110 (F-9).** The communications log is on the mission radio page,
not only on `/radio-legacy`. Transmissions on either radio, sent or received,
add a row (date, Zulu time, net, station, duration); the operator writes the
traffic into the editable cell, or adds an entry for something heard another
way. Export writes a fixed-width `CAPF110_<station>_<date>.txt`. The log is held
in the page and autosaved to the tab's `sessionStorage` on every change, so a
reload, back-swipe or iOS tab eviction restores it; closing the tab ends it, so
export before finishing. Nothing is sent to the console and it is not an actual
mission record.

## Radio selection and artwork

These are two CAP-documented mobile/base radio families, selected from training
references, **not a verified nationwide inventory ranking**:

- **Motorola APX 4500 with O2 control head:** [CAP Louisiana Wing ICUT review](https://www.member.lawg.cap.gov/PDF%20Docs/Comms/ICUT%20Practical%20Exam%20Review%20Guide.pdf),
  PDF pages 47–48 (base/mobile introduction and control diagram).
- **EFJohnson 5300 series:** legacy EFJohnson mobile photograph on PDF page 34
  in the same review, with the model family explicitly identified on slide 36
  of the [CAP New Hampshire Wing ACUT presentation](https://slideplayer.com/slide/4644303/)
  (CAP-authored material, third-party hosting).

The ICUT PDF is saved as `icut-review.pdf` alongside this document. Faceplates
are original SVG artwork generated by `scripts/make_base_radio_artwork.py`.
They use reference-informed control positions, matte housing, restrained
lighting and smooth browser text overlays. Downloadable faceplates are in
`services/exercise/app/static/radio-art/`; PNG previews with active displays
are in `output/mission-base-radio/`. Regenerate SVGs with Python 3:

```sh
python3 scripts/make_base_radio_artwork.py
```

The face controls provide power/join, channel/net selection, home, and volume
where mapped, plus MON on the EFJohnson face. Hover/focus labels identify active
controls. The other printed SCAN, SQL and emergency controls are visual
references, not implemented hardware functions. Real radio softkey programming
varies by fleet. Displays use training net names, not a CAP frequency/codeplug
plan. There is no RF gateway, ATC bridge, scan or dual-watch emulation (the two
receivers are independent), encryption emulation or audio recording. The older
APX6500/Icom typed-message console remains at `/radio-legacy`; the new page
logs transmissions to its own Form 110 but does not transcribe voice.

## Architecture

```text
Bluetooth / wired headset
  ↕ browser getUserMedia + AudioWorklet (48 kHz mono)
trusted HTTPS / WSS :443
  ↕ Caddy reverse proxy
FastAPI exercise service :8700 /api/radio/stream
  ↕ one pymumble client per connected browser (TCP-tunneled Opus)
existing Mumble server :64738
  ↕ selected mission net
native Mumble crews + other browser stations
```

Upstream [pymumble](https://github.com/azlux/pymumble) is pinned to commit
`a560e6013dfbccb3666ce8756e1ca6b790bf05c8` rather than the older PyPI 1.6.1
release, which uses removed Python SSL APIs. Docker installs native `libopus0`.
The native Mumble connection uses upstream's self-signed-compatible TLS behavior;
it does not validate the Mumble server's certificate. Keep that backend
connection on the trusted compose network. Browser HTTPS is separately verified.

PTT is independently gated in the browser and server. The microphone track is
disabled until the server acknowledges a held PTT request. Stale acknowledgments
cannot open a released microphone. Pointer cancellation, page blur, hidden page,
retuning, disconnect, congestion and a 60-second limit release TX. A 1.5-second
server lease also stops TX if keepalives cease. Muting or moving a native client
on the server stops its browser's next TX frame. Retunes wait for the Mumble
channel acknowledgment; old audio is discarded using a channel generation tag.
Receive audio is filtered to the selected channel and muted while transmitting.
Queues are bounded; per-user pymumble receive queues are consumed after copying
each packet. Closing a tab stops its native client and releases the session slot.

Config API: `/api/radio/config`. WebSocket: `/api/radio/stream`.
Outgoing PCM is one 20 ms / 960-sample signed int16 little-endian mono frame.
Incoming binary packets prepend uint32 channel generation and uint32 speaker ID.
Control messages are JSON. Origin checks reject cross-site browser connections.
Passwords remain on the server; optional exercise access codes are checked there.

## Server configuration

Compose adds the voice settings to `exercise` and a `radio-https` Caddy service.
Existing exercise data stays in the original bind-mounted database directory.
The proxy uses standard HTTPS port 443 and is also the front door for the
exercise console and planner. No router forwarding is needed or configured.

| Variable | Default / use |
|---|---|
| `CAPVSAR_MUMBLE_HOST` | Required; `mumble` in Compose |
| `CAPVSAR_MUMBLE_PORT` | `64738` |
| `CAPVSAR_MUMBLE_PASSWORD` | Existing `MUMBLE_SERVER_PASSWORD`, server-side only |
| `CAPVSAR_MUMBLE_CHANNEL_PREFIX` | Optional parent channel path |
| `CAPVSAR_RADIO_ACCESS_CODE` | Optional shared browser exercise code |
| `CAPVSAR_RADIO_MAX_SESSIONS` | `16` per exercise process |
| `CAPVSAR_RADIO_HTTPS_PORT` | `443`, used for the browser's secure-page link |

Channel mapping is in `app/radio.py`: PRIMARY → `Mission Net PRIMARY`, ALTERNATE
→ `Mission Net ALTERNATE`, MISSION BASE → `Mission Base`, BRIEFING → `Briefing Room`.
These channels must already exist and permit the connecting users to join/speak.

To install/update from `/srv/capvsar`, after copying the changed source files:

```sh
mkdir -p services/exercise/radio-public
docker compose build exercise
docker compose up -d --no-deps exercise radio-https
docker cp capvsar-radio-https:/data/caddy/pki/authorities/local/root.crt services/exercise/radio-public/mission-base-ca.crt
chmod 644 services/exercise/radio-public/mission-base-ca.crt
```

Only the public `root.crt` is copied. The read-only `/radio-public` bind mount
lets `/radio-ca.crt` distribute it. Do not copy `root.key`. Preserve the named
Caddy volumes between deployments so existing devices retain trust. The Caddy
file supports `ms01`, `ms01.local` and `192.0.2.151`; change it and setup links
if the mission host address changes. The first deployment's rollback files
are on ms-01 in `/srv/capvsar/backups/mission-radio-20260908/`.

`default_sni 192.0.2.151` is required for IP-address TLS clients behind Docker.
The installed public CA SHA-256 fingerprint is
`AE:D7:ED:5D:10:5B:BD:27:D6:00:BF:8F:52:AD:AE:44:66:20:60:78:B2:9A:2B:81:B4:62:6E:40:B9:AC:5C:2A`.

## Verification

Backend regressions (Python 3.12, install exercise requirements plus pytest/httpx):

```sh
python3 -m pytest tests/test_radio.py -q
```

Twelve tests cover PTT gating, release, independent stations, access-code and
origin checks, credential privacy, malformed audio, lease/maximum TX duration,
channel isolation, retune acknowledgment, server mute and server-initiated move.

For full audio verification, create a **disposable, separately authenticated
Mumble server** and the four channels listed above. Start a separate exercise
process on localhost configured for that test server and a temporary database.
Install Playwright and Google Chrome, then run:

```sh
python3 scripts/test_base_radio_browser.py http://127.0.0.1:8820
```

This script sends synthetic audio. Never use a live exercise instance or tunnel
the live exercise service to that test URL. It launches two real Chromium
sessions, sends a tone through browser capture → Mumble Opus → browser playback,
measures the receiver's output, and verifies release, blur, focus exclusions,
different-net silence, pointer cancellation and responsive layouts. It also
exports the instrument and desktop/tablet/phone screenshots. The local-host URL
guard is a convenience; the operator must still configure an isolated backend.

Validated with Chromium synthetic microphones and a real isolated Mumble server.
Physical Bluetooth headsets, iPad Safari, Android and long-duration/WAN behavior
still need device acceptance testing. Bluetooth routing and call-mode audio
quality depend on the device. This implementation is for the existing LAN/VPN
exercise service, not an authenticated public multi-tenant voice service.
